# Evidence notes

Raw benchmark stdout/stderr and command JSON live under benchmark/. summary.json aggregates actual redis-benchmark CSV columns; its metadata includes machine/compiler/build flags and tool version/hash. Compiler paths describe the measurement host, not a runtime dependency. render_readme.py reads these outputs rather than inventing numbers. Each sanitizer run writes separate histories/caught-failure results, so the normal workload evidence is not overwritten.

Actual caught system failures: build/caught-failures.json contains malformed/over-quota commands rejected with original value retained. build/corruption-rejected.log includes startup refusal after an intentional snapshot byte flip. build/histories.json includes the stale-read negative control, which must be rejected. Normal exit from those tests means the fault gate worked.

Retained development failures: ASan's first detect_leaks option was unsupported on macOS (asan-unsupported-leak-option.log); subsequent ASan runs explicitly disable that option locally, while Linux CI enables it. The first sanitizer integration harness created its output directory only under __main__, causing pytest artifact writes to fail; directory creation moved into setUpClass (asan-initial-harness-failure.log and tsan-initial-harness-failure.log retained). The initial formatter package pin matched a Homebrew-only version, not a PyPI wheel; initial-formatter-package-failure.log records it, requirements-dev.txt pins an available release. Browser recording initially expected different cached browser/video revisions; initial-browser*/initial-video* logs retain those environment failures. Matching tools are installed only into the workspace cache for the completed rerun.

These are not storage correctness bugs, sanitizer-clean claims for failed runs, or erased evidence. Consult final named logs for the completed gates. Timing counts/checks represent finite workloads, not mathematical proof of all histories or production capacity.

The recorder also caught its own eval-based wait conflicting with the strict CSP; initial-recorder-csp-failure.log is retained. Locator assertions replaced that wait without weakening the policy. The completed video is demo.webm, with raw ffprobe metadata in browser/demo-probe.json. Binary data is JSON-escaped in transport and decoded as Latin-1 for text display; it is never HTML.

Linux CI found a genuine data race on the original volatile sig_atomic_t shutdown flag: it was signal-safe but not synchronization for native worker threads. initial-linux-tsan-race.log preserves the report. The fix uses an always-lock-free atomic bool and relaxed load/store; no TSan suppression or gate bypass. The Docker GCC build also rejected const-char-prefix/rvalue string concatenation under -Werror=restrict. Explicit append-based bulk/integer response construction keeps the strict warnings enabled; initial-container-compiler-failure.log preserves it. Final gates must rerun both modes.
